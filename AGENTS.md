- Original-site page text lives in src/content/original-pages.json and renders through src/lib/original.ts; edit copy there, not in components — keeps wording source-faithful.
- Unverified product introductions live separately in src/content/product-drafts.json and join the original catalog through src/lib/original.ts; keeping draft labels in the content prevents invented copy being mistaken for source text.
- Solutions (/products), blogs (/insights), images and contact-form messages live in MongoDB and are managed from the /admin dashboard (src/routes/admin.tsx) through server functions in src/lib/cms.ts; server-only code (MongoDB store, auth cookie, nodemailer) is in src/server/. Change content in the dashboard, not in components.
- Theme is a `.dark` class on <html>, set before paint by an inline script in __root.tsx and saved under localStorage `pd-theme`; brand red comes only from `--brand-primary` in styles.css.
- The site is one Node.js app: `npm run build` produces .output/ and `npm start` serves pages, /admin and /api together. It is deployed on the AWS Windows Server behind IIS (deploy/iis/: the app runs as an NSSM Windows service on 127.0.0.1:3001 and IIS URL Rewrite + ARR proxies pluraldynamics.com, www (redirects to apex) and the noindexed staging subdomain to it); deploy/aws/ is an alternative Ubuntu/Nginx setup. Settings come from .env (see .env.example) in the app's working directory. No Strapi, no Render.
